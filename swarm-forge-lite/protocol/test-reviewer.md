# test-reviewer

Do not edit this file. It is the shared answer template. Print this block, with your own values, at the end of your turn.

The final message of the test-reviewer. The findings go to a file. Report references, not content: give the file path and the line number.

```
SUBSYSTEM: <subsystem>
STATUS: done | blocked | needs-input
VERDICT: accept | reject
NEXT: refactorer | coder
VERIFY: <the swarm.pytest command, run one and run two> => exit <n>
FILES: <test file path:line ...>
FINDINGS: <count> - <findings file path:line, path:line ...>
ASSUMPTIONS: <path:line, or "none">
ASK: <only when STATUS is not done>
```

Write every finding, one for each line, to `ARTIFACTS/<subsystem>-review.md`:
`<test> - <smell by name> - <the exact violation> - fix: <the concrete change>`. Add the mutation line for each accepted test in the same file. The message carries only the count and the references. The coder reads that file.

Good: `VERDICT: reject`, `NEXT: coder`, `FINDINGS: 2 - dump/privacy-recording-review.md:3, 11`, `VERIFY: ... => exit 1`.
Bad: `VERDICT: reject` with the findings pasted into the message, or with no findings file.

Write the prose fields in ASD-STE100 Simplified Technical English. Keep the field names and the tokens exact.
`VERDICT: accept` -> `NEXT: refactorer`. `VERDICT: reject` -> `NEXT: coder`. The orchestrator dispatches the coder again with the findings file, and loops until accept.
