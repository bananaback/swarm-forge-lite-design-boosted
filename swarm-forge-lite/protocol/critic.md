# critic - design answer

Do not edit this file. It is the shared answer template. Print this block, with your
own values, at the end of your turn.

The final message of the critic. It reads the union of the accepted modules and the
frozen interfaces, and writes the subsystem `SKELETON.md`. The forms live in the
work files. Report references, not content: give the file path and the line number.

```
SUBSYSTEM: <subsystem>
ROLE: critic
STATE: settled | open | blocked
WORK: design/subsystems/<subsystem>/04-critic/
SKELETON: design/subsystems/<subsystem>/SKELETON.md
STOP TEST: pass | fail
DECISIONS: <n>
  D1 [<named rule: skeleton acceptance, OCP seam, cross-module dedup, contradiction>] <path:line> - <one-line question> | options: <a> | <b> | <c> | answer: <operator's>
FOR OTHER ROLES: <path:line - route to <role>, or "none">
OPEN RISKS: <design defaults and assumptions, or "none">
NEXT: <coder | operator>
```

Good: `STATE: settled`, a DECISION per skeleton acceptance or OCP seam with the rule
named and the file line, `STOP TEST: pass`, `NEXT: coder`.

Bad: the union skeleton pasted into the message, or a module that violates its frozen
interface.

`STATE: settled` means that the operator accepted the skeleton at the gate and every
module honored its frozen interface. **A new DECISION makes `settled` illegal: return
`STATE: open`.** Keep each `DECISION` to one line.

The accepted skeleton is at `design/subsystems/<subsystem>/SKELETON.md`. Give its
path and lines. Do not paste it. `NEXT` is `coder`.
