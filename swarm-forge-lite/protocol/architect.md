# architect - design answer

Do not edit this file. It is the shared answer template. Print this block, with your own values, at the end of your turn.

The final message of the architect. It cuts the subsystem into modules and freezes
the interfaces. The forms live in the work files. Report references, not content:
give the file path and the line number.

```
SUBSYSTEM: <subsystem>
ROLE: architect
STATE: settled | open | blocked
WORK: design/subsystems/<subsystem>/02-architect/
ARCHITECTURE: design/subsystems/<subsystem>/02-architect/ARCHITECTURE.md
INTERFACES: design/subsystems/<subsystem>/interfaces/   (<n> files)
STOP TEST: pass | fail
DECISIONS: <n>
  D1 [<named rule: module cut, Parnas merge/split, SRP split, DIP seam, ambiguous noun>] <path:line> - <one-line question> | options: <a> | <b> | <c> | answer: <operator's>
FOR OTHER ROLES: <path:line - route to <role>, or "none">
OPEN RISKS: <design defaults and assumptions, or "none">
NEXT: designer
```

Good: `STATE: settled`, a `DECISION` per module cut or merge with the rule named
and the file line, `STOP TEST: pass`, `NEXT: designer`.

Bad: the CRC cards pasted into the message, or a module whose write set overlaps
another module.

`STATE: settled` means that the operator resolved every module `DECISION` at the
`question` gate, the freeze checklist passes, and the acceptance walk found no
open crossing. **A new DECISION makes `settled` illegal: return `STATE: open`.**
Keep each `DECISION` to one line: the question names the `path:line` that carries
the context.

The accepted map is in `design/subsystems/<subsystem>/02-architect/ARCHITECTURE.md` and
the interfaces are in `design/subsystems/<subsystem>/interfaces/`. Give their paths and
lines. Do not paste them.

`NEXT` is `designer`. The orchestrator then splits the module map and dispatches
one designer for each module.
