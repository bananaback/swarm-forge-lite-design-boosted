# specifier

Do not edit this file. It is the shared answer template. Print this block, with your own values, at the end of your turn.

The final message of the specifier. The feature is the artifact. Report references, not content: give the file path and the line number.

```
SUBSYSTEM: <subsystem>
STATUS: done | blocked | needs-input
APPROVED: yes | no
NEXT: <architect | interrogator>
VERIFY: <parse + dry-check command> => exit <n>
FILES: <feature path:line, IR path, dry path>
ASSUMPTIONS: <path:line, or "none">
ASK: <only when STATUS is not done>
```

Good: `STATUS: done`, `APPROVED: yes`, `NEXT: architect`, `VERIFY: gherkin-parser ... && ir-dry-checker ... => exit 0`, `FILES: login.feature:8, login.json, login.dry.json`, `ASSUMPTIONS: none`.
Bad: `STATUS: done` with no `VERIFY`, or the scenarios repeated in the message.

Write the prose fields in ASD-STE100 Simplified Technical English. Keep the field names and the tokens exact.
`APPROVED: yes` means that the operator answered `Approve` at the `question` gate. Approval opens the design gate, and the orchestrator next dispatches the **architect**. `NEXT: interrogator` returns a defective record to the interrogator.
