# design/

Durable, operator-owned design state produced by the requirement and design roles
(`interrogator`, then `modeler -> contractor -> critic`). One directory per task:

```
design/<task>/
  BLUEPRINT.md              # the accepted artifact: REV n + [DRAFT|ACCEPTED]; immutable after accept
  SKELETON.md               # the critic's implementation contract; the coder and refactorer read this
  work/
    01-interrogator.md      # the interrogator's full filled forms (its state)
    02-modeler.md
    03-contractor.md
    04-critic.md
  model.json                # topology for the visual view
  model.html                # generated by umlview render.py; reload with F5
```

The method is `swarm-forge-lite/protocol/design-procedure.md` (step index). The team
protocol — input dispatch, output answer, working state, revision rules — is
`swarm-forge-lite/protocol/design-protocol.md`. Technique definitions are in
`swarm-forge-lite/reference/design-craft-design.md`; stop tests, ownership, and loop control in
`swarm-forge-lite/reference/design-quality.md`. The empty fill-in forms are under
`design/templates/`; each role copies its own template to `design/<task>/work/<nn>-<role>.md`
and fills every form.

Rules:

- `BLUEPRINT.md` holds the accepted projection only. The raw work lives in `work/`; a
  role edits its own working file and the blueprint sections it owns, and nothing else.
- Sections are `DRAFT` until the operator accepts them; then `ACCEPTED` and immutable. A
  later change is a `[REVISION REQUEST]` line that increments REV and marks the changed span —
  never an in-place edit, and no revision log is kept.
- Durable and operator-owned: never written into the project tree, never cleaned by
  `harness clean`, never under `dump/`, `hot_tests/`, or `.swarmforge/`.
- The operator commits blueprints; roles never commit.
