# design/

Durable, operator-owned design state produced by the requirement and design roles
(`interrogator`, then `architect -> designer x N -> critic`).

**The unit of design is the subsystem.** One living record for each subsystem, edited in
place. There is no per-task directory, no revision, no status and no change log: the
latest content of a file is its whole truth. A change to a subsystem is an edit to its
record.

```
design/subsystems/<subsystem>/
  01-interrogator/          the interrogator's sections, one file per section
  02-architect/             the architect's sections, and ARCHITECTURE.md (the module map)
  interfaces/               THE FROZEN INTERFACES - one living file for each module
    <module>.md
  modules/                  one record for each module
    <module>/               DESIGN.md + SKELETON.md + decisions.md
  04-critic/                the critic's sections
  specifier/                the specifier's own note, when it writes one (SELFCHECK.md,
                            ASSUMPTIONS.md). The specifier has no numbered section.
  coder/                    the coder's own note, when it writes one (IMPLEMENTATION.md)
  SKELETON.md               GENERATED by `swarm.genRecord`: the critic's cross-module
                            brief from `04-critic/3-skeleton.md`, plus every module's
                            `SKELETON.md`. Do not hand-edit it. Author the brief in
                            `04-critic/3-skeleton.md`, and the contracts in the modules.
  COUNTS.md                 generated by `swarm.genRecord`; cite it, do not hand-count
  CONTRACTS.md              generated by `swarm.genRecord`; cite it, do not hand-copy
  model.json                the topology for the visual view (source of truth for the diagram)
  model.html                generated by umlview `render.py`; reload with F5
  model.live.json           generated by `swarm.umlSync` (the refactorer's step); the
  model.live.html           publish reads the live overlay when it exists
```

The requirement document lives outside the record, at `<SPECS>/NN-<subsystem>.md`
(the `SPECS` root from `harness.json`). It is a VIEW of the record:
`swarm.genDoc` syncs each row the document already carries to the record's own id
and wording, IN PLACE, and every other line - the headings, the subheadings, the
prose - stays. Author the TABLE in the record. Never hand-edit a row of the
document, and never let it carry a second numbering space.

The subsystems are the design domains of the wired project: one directory for each. A new
subsystem is one new directory. A change to a subsystem is an edit to its record - never a
new directory.

A subsystem directory that holds only `GOAL.md` is PLANNED, not started: it carries the
intent and no design yet. Do not read one as a record, and do not delete it.

The method is `swarm-forge-lite/protocol/design-procedure.md` (step index). The team
protocol - input dispatch, output answer, working state, editing rules - is
`swarm-forge-lite/protocol/design-protocol.md`. The freeze and the parallel split are
`swarm-forge-lite/reference/module-rules.md`. Technique definitions are in
`swarm-forge-lite/reference/design-craft-design.md`; stop tests, ownership, and loop
control in `swarm-forge-lite/reference/design-quality.md`. The empty fill-in forms
are under `design/templates/`; `harness.py init-work <role> --subsystem <subsystem>` writes
them into the subsystem's role directory when the record is new. For a designer, pass
`--work design/subsystems/<subsystem>/modules/<module>`.

Rules:

- Each role fills the section files of its own role directory, and edits them in place.
  The role sections **are** the record; the role sections are the record.
- A role may ADD a section file of its own beyond the numbered list, when the work needs
  it, named in the same house shape (`0B-tracker-metadata.md`, `10b-candidate-cases.md`,
  `8b-sufficiency-gate.md`). The numbered list is the minimum, not a maximum. Never delete
  another role's added section.
- A build role has no numbered directory. The specifier and the coder may keep their own
  note in `specifier/` and `coder/` when they have one to write.
- One home for each fact. The `01-interrogator/` sections are the home of the
  requirement facts. A root `goal.md`, `constraints.md`, `requirements.md`, or
  `exclusions.md` is a dead legacy projection: cite the section, never the projection.
  The method contracts have one home, `modules/<module>/SKELETON.md`; the subsystem
  `SKELETON.md` is the critic's projection of them. The decision table of a
  role has one home, `decisions.md` in its work directory.
  `COUNTS.md` and `CONTRACTS.md` are generated by `swarm.genRecord`: cite them, and
  never hand-count a number or hand-copy a contract.
- The design section sets are small. The architect keeps `1-grammar` (grammar +
  cross-cutting verbs), `2-crc-cards` (cards + secrets + SRP), `3-structure`
  (core/shell + dependency graph + state map), `4-module-map` (module map +
  acceptance walk + visual), `ARCHITECTURE.md`, and `decisions.md`. The critic
  keeps `1-review` (extension + substitutability + trim), `2-economy` (dedup +
  minimalism + naming), `3-skeleton`, `4-visual-gate`, and `decisions.md`.
- The stop test is printed by `swarm.check`; no role transcribes it into a file.
- The subsystem name and the `LANE` are the same string. Never work in, nest, or rename
  another subsystem's directory.
- The record is one version per subsystem: no revision, no status flag, no change log.
  The latest content of a file is its whole truth.
- Durable and operator-owned: never written into the project tree, never cleaned by
  `harness clean`, never under `dump/`, `hot_tests/`, or `.swarmforge/`.
- A change is a **delta pass**: read the subsystem record, then edit only the section files
  the change touches and add only the rows and sections it needs. Never copy a template
  over the record and never regenerate an untouched table.
- The operator commits the record; roles never commit.

The `design/<task>/` packs were the earlier per-task workflow. Every subsystem's
record is synced and current, so every per-task pack is removed. There is one
directory for each subsystem, and no other. The subsystem record is the truth.

The design team is `architect -> designer x N -> critic`. `design/subsystems/` holds
one directory for each subsystem, and `design/templates/` holds the empty forms.
