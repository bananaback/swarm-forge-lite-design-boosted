## 0A. SPEC — the requirement document

Resolve the requirement document before framing. Refine an existing draft to match the accepted record; create the doc when none exists. House shape: `# NN — <name>`, then Purpose · Scope (in/out) · Definitions · Requirements (`- Rn — <statement>`) · Acceptance Criteria (`- ACn — <check>`) · Constraints. One-to-one with the record's Rn/ACn. Business vocabulary only: no token in code marks, no path, no file name, no class or element name, no framework or library name. A class name and a path belong to the design record alone.
